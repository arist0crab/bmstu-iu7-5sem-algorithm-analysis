# Лабораторна работа №1

Сравнение временной эффективности нерекурсивных и рекурсивных алгоритмов, решающих одну задачу.

Для разных групп предлоставлены разные варианты задания этой лабораторной работы, данное условие предоставлено для варианта №54: алгоритм поиска в массиве.

Источник, вдохновитель и автор конспекта с семинара: [@djstrawberry](https://github.com/djstrawberry/algorithm_analysis_iu7_software_engineering_2028/tree/main/lab_01)

## Задание

В рамках лабораторной работы предстоит реализовать 4 алгоритма:
1. Линейный алгоритм поиска элемента в массиве - полный перебор элементов.
2. Бинарный нерекурсивный алгоритм поиска элемента в массиве - классическая реализация.
3. Бинарный нерекурсивный алгоритм поиска элемента в массиве - как-либо модифицированная версия классического бинарного поиска.
4. Бинарный рекурсивный алгоритм - классическая рекурсивная реализация.

Для каждого алгоритма необходимое реализовать две его версии: 
- _основная_: возвращает только индекс найденного элемента
- _расширенная для сбора данных_: возвращает дополнительную информацию, такую как количество выполненных сравнений, глубину рекурсии, кол-во шагов и итераций и т.д.

## Дополнительные требования

1. Язык, используемый при выполнении ЛР, должен быть со статической типизацией.
2. Все алгоритмы должны работать с одним и тем же массивом. Не имеет значения, будет ли это оригинал этого массива или его копия, главное, чтобы массив был точно таким же для чистоты эксперимента.
3. Массив заполняется произвольными различными значениями одного числового типа. Пользователь должен иметь возможность ввести числовое значение `N` - количество элементов массива.
4. Перед запуском бинарных алгоритмов массив должен быть отсортирован по возрастанию. Сортировка выполняется один раз, её сложность не учитывается при сравнении алгоритмов, но должна быть упомянута в отчете как дополнительная затрата.

Программа должна работать как интерактивный стенд. Пример такой реализации:

```
1. При запуске программа запрашивает у пользователя размер массива N.
2. Генерирует массив из N различных чисел (например, случайных).
3. Выводит меню, в котором пользователь может:
- ввести искомое значение x;
- выбрать алгоритм поиска (1–4);
- увидеть индекс найденного элемента (или сообщение об отсутствии).
4. Цикл повторяется, пока пользователь не завершит работу.
```

## Критерии сравнения эффективности алгоритмов

| Алгоритм  | Временная сложность[^1] | Ограничения алгоритма[^2] | Затраты по памяти | 
| ------------- | ------------- | ------------- | ------------- |
| Линейный поиск  |  Лучшая: 1<br>Худшая: N | Нет | i → O(1) |
| Классический бинарный поиск | Лучшая: O(1)<br>Худшая: O(log₂N) | Сортировка | L, R, M → O(1) |
| Модифицированный бинарный поиск | Зависит от модификации | Сортировка | Зависит от модификации |
| Рекурсивный бинарный поиск | Лучшая: O(1)<br>Худшая: O(log₂N) | Сортировка | Каждый рекурсивный вызов добавляет кадр в стек. Глубина = log₂N |

[^1]: Под временной сложностью алгоритма подразумевается асимптотическая оценка количества операций сравнения, выполняемых алгоритмом в зависимости от размера входного массива N.
[^2]: Любой бинарный поиск требует отсортированного массива. Это влечёт дополнительные затраты: на вставку с сохранением порядка и на начальную сортировку. Сортировка выполняется один раз и не учитывается при сравнении алгоритмов поиска.

## Лучшие и худшие случаи

На защите лабораторной работы и в отчете необходимо будет затронуть тему лучших и худших случаев для каждого из алгоритмов.

Говоря о рекурсивной эффективности, будем называть при фиксированном значении `N` лучшим случаем оценки эффективности минимум по всем возможным исходам, худшим случаем, соответственно, максимум. Пример: поиск элемента в массиве полным переброом потребует минимум 1 сравнение, 1 - оценка числа необходимых сравений в лучшем случае.

Для любого из упомянутых случаев возможно назвать 1 и более условий наступления такого случая. Так, при поиске полным перебором условие наступления произвольного случая - не первый и не последний элемент, однако, он все равно должен быть в массиве.
